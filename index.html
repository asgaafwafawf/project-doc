最终交付物：output/工程设计AI大模型系统_安装包_v2.2.exe（647 MB · Windows 10/11 x64 · 免环境、免管理员）

tools/ 下的那些 exe 是这套系统调用的引擎，不是交付物本身。
用户拿到的只有一个安装包：装完即用，能对话、能读图、能查规范、能直接出《施工图审查意见》。

1. 这是什么

一个把「看图 → 提数 → 判别 → 出报告」串成一条流水线的桌面 AI 系统：

  • 对话即操作：用自然语言下达审查任务，Agent 自行决定调哪个工具、下一步做什么；
  • 真正下地干活：DWG 转换、图层/文字提取、图纸渲染、PDF 解析、GB 50010 合规判别，全部本地可执行（部分环节需联网调模型）；
  • 证据可追溯：每条结论标注证据等级（A 结构化提取 / B 看图转录 / C 推算 / D 无法确认），精确文字一律以结构化提取为准；
  • 输出对标正式审查意见表：强条问题置顶，按「强条 → 符合性 → 技术性（A/B/C 类）→ 结论」组织。

典型使用场景：拿到一册施工图（DWG/DXF/PDF）和计算书，希望在一轮对话内得到一份可复核的审查问题清单。

2. 快速开始

2.1 环境要求

项要求

运行环境无需安装 Python、Node.js、Office、CAD

2.2 安装

  1. 双击 工程设计AI大模型系统_安装包_v2.2.exe（未做代码签名，若弹出 SmartScreen 提示，选「更多信息 → 仍要运行」）；
  2. 一路 Next（安装向导为英文，脚本未挂中文语言包，不影响使用）；
  3. 默认安装到 %LOCALAPPDATA%\Programs\施工图审查助手，安装目录内含 结构审查工具箱\；
  4. 开始菜单 →「施工图审查助手」→「工程审图智能助理」启动；安装脚本默认不勾选桌面图标，需要时重新运行安装程序勾选，或手动发送快捷方式。

安装包校验（可选）：

SHA256  305A9B01C59157329EA1FAF79435A600FB15AB6E4280010672FAD634D2A67231
文件大小 662,914.2 KB (647.4 MB)

安装后有三个名字同时存在：安装包叫「工程设计AI大模型系统」、程序名/卸载项叫「施工图审查助手」、快捷方式沿用旧 exe 名「工程审图智能助理」。三者是同一个系统，窗口标题显示「工程设计AI大模型系统」。

2.3 配置模型接口

首次使用需接入一个 OpenAI 兼容接口：

  1. 界面左下角「设置」→「开发者配置（AI 接口）」（需开发者密码，见 10.1）；
  2. 填写 base_url / api_key / model；
  3. 默认预置 MiniMax-M3（https://api.minimaxi.com/v1），可改为 DeepSeek、通义、Kimi、vLLM 等任意 OpenAI 协议服务；
  4. 若所用模型支持多模态，可打开 主模型多模态（native_vision），此时看图由主模型直接读图，无需另外配置视觉接口；
  5. 配置保存在 %APPDATA%\结构审查助手\config.json，不写入安装目录（安装目录不可写也能正常用）。

2.4 跑第一次审查

  1. 新建任务（左侧任务栏可并行开多个，互不干扰）；
  2. 把图纸目录或文件拖进输入区（支持文件/文件夹，上传即右侧预览）；
  3. 描述诉求，例如「审查这份结构施工图，重点看配筋与规范强条」；
  4. 观察五步进度条：识别图纸 → 解析内容 → 结构分析 → 规范核查 → 形成报告（界面上有预计耗时，异常时可直接点停止，秒级中断）；
  5. 报告生成后，在报告卡片上选择 md / docx / html 导出。

4. 审查流水线

4.1 目录约定

把图纸按下列结构摆放，系统会自动识别（详见 使用说明.txt）：

某工程\
├─ 施工图图纸\      ← DWG / DXF
├─ 设计pdf\         ← 出图 PDF
└─ 计算书\          ← doc / docx

4.2 六个环节

步骤做什么关键点
0 盘点核对图纸/PDF/计算书是否齐全缺件直接写进报告的「符合性审查」
1 转换DWG → DXF；PDF → 文字层优先 ODA File Converter，失败回退内置 LibreDWG
2 提取产出 .cad.json + .cad.md先读 md 建立全局认知，再查 json 取精确值；>10 MB 的 DXF 用 dxf_text_extract
3 看图渲染 PNG/PDF 后读图主模型多模态用 view_image，否则用独立视觉接口
4 判别构件参数 → GB 50010 合规检查输出 PASS / FAIL / MANUAL_REVIEW，覆盖 498 条、100%
5 成文汇总为审查意见强条置顶，按 A/B/C 分级，附修改要求

转换质量判据：ODA 生效时结构化文字可靠，可直接采用；若回退到 LibreDWG，转出的 DXF 异常小（通常 < 2 MB）或出现明显不属于本图的词组，说明文字可能被错误重组 —— 此时改走看图路径，并以看图结果为准。

PDF 读法：优先读文字层；栅格化 PDF（无文字层）才走看图转录，并按 B 级标注、提示关键数值人工复核。

4.3 证据分级

等级来源标注要求
A结构化文字提取（DXF 实体、PDF 文字层）默认不标注，视为可信
B看图转录必须标「（视读）」
C由 A/B 推算标「（推算）」并附算式
D无法确认列入文末清单，不臆造

铁律：文字看提取，图形看视觉；两者冲突时，精确文字永远以结构化提取为准。 严禁仅凭看图读到的文字差异就判定「图纸来自不同项目」「工程名称不一致」。

4.4 报告结构

表头只写工程名称，正文四段：

  1. 一、规范强条审查发现的问题 —— 只收违反强制性条文的问题，无则明确写「未发现」；
  2. 二、符合性审查 —— 送审资料的完整性（初设批复、盖章签字版、计算书、合同等）；
  3. 三、技术性审查 —— A 类（影响安全）/ B 类（一般问题）/ C 类（待核），逐条编号，给位置、依据、数值对比、修改要求；
  4. 四、审查结论 —— 1–3 条短结论 + 送审说明。

口吻对标正式《施工图设计文件审查意见表》：专业、简洁、命令式，不寒暄、不模糊。

7. 提示词库

提示词库/ 收录「图纸内容描述」类专业提示词，用于让模型按固定口径逐图转录：

编号文件专业版本
00库索引与使用规则入口，互斥选择铁律—
01排水工程提示词市政给排水施工图v6

规则很简单也很难绕开：一次任务只加载一个提示词，命中判定特征 ≥3 条才选定，无法唯一判定就停下来问用户，禁止拼接混用。

配套的 校验器/*.py 需要本机 Python + ezdxf，打包版未集成 —— 跑不起来时如实跳过，不得虚构校验结果；权威数据模板/*.json 只是格式示例，禁止直接复用到别的工程（会造成系统性错配 FAIL）。

10. 开发与构建

10.1 源码运行

# 桌面版（v2 界面，推荐）
python gui_app_v2.py        # 依赖：tkinterdnd2、Pillow、PyMuPDF(fitz)、python-docx

# Web 版
python server.py            # 零第三方依赖，浏览器打开 http://127.0.0.1:8765

GUI 采用「prompt 驱动的 JSON-action 循环」（ReAct 风格），不依赖特定厂商的 function-calling，因此任何 OpenAI 兼容聊天模型都能驱动。

开发者密码：AI 接口配置藏在「开发者配置」里，口令写死在 gui_app_v2.py:2363 的 DEV_PASSWORD。它只是本地防误触的门槛，不是安全机制；分发前请把它换成自己的值，并且不要把含 Key 的 config.json 一起打包。

10.2 构建 exe

cd 审查助手
python -m PyInstaller build_desktop.spec --distpath dist --workpath build

三条踩过的坑（详见 审查助手/打包exe必备文件清单.md）：

  1. 入口必须是 gui_app_v2.py（审查助手_桌面版.spec 是 v1 入口，别混用）；
  2. excludes 严禁包含 lxml（docx 导出依赖它），hiddenimports 必须有 pkg_resources、setuptools、jaraco.*；
  3. 只对 4 个依赖做 collect_all（tkinterdnd2 / PIL / fitz / docx），否则 Analysis 会因拉入整个环境的依赖图而卡死几十分钟。

10.3 重新打安装包（发布新版必读）

当前 installer.iss 里的 SrcRoot 仍指向已失效的旧路径（D:\kimi\…），且 OutputBaseFilename 固定为 …_v2.2：

  1. 改 SrcRoot 为本机仓库根目录（如 E:\结构审查工具箱）；
  2. 把 [Icons]、[Run] 的目标由 工程审图智能助理.exe 改为 工程设计AI大模型系统.exe（否则快捷方式仍指向 8 月的旧程序）；
  3. 把 OutputBaseFilename 顺延为 …_v2.3（同名会直接覆盖 v2.2）；
  4. 用 Inno Setup 6 编译 installer.iss，产物落在 output\；
  5. 建议显式设置 AppId 并长期保持不变，否则改名会产生两条独立的卸载记录。

11. 已知限制

  • 高版本 DWG：ODA 不可用而回退 LibreDWG 时，文字可能被错误重组（判据见 4.2），需改走看图；
  • 扫描件 PDF：无文字层，只能看图转录，关键数值建议人工复核；
  • PDF 解析：Infinity-PDF-Parser 依赖外部解析服务器，未配置时该环节不可用，不影响 DWG 路径；
  • 提示词库校验器：需要本机 Python + ezdxf，安装包内没有，相关校验会跳过并说明；
  • 杀毒软件：PyInstaller 打包的程序偶发误报，加白名单即可；
  • 模型依赖：审查质量与所用模型强相关，弱模型可能不遵守工具调用格式或漏读证据等级。
